# Axiom Chronos 3.0.0-beta.1

Axiom Chronos 3.0.0-beta.1 is a GitHub pre-release of 3.0. The engine now runs each unit's build, verification, acceptance and review pack in one call, starts a module as soon as the modules it depends on are verified, and routes every unit to a Codex tier. Wishes keep running in a background service after the window closes. New are a native code and memory graph, storage accounting with a disk guard, modes beyond the wish, and desktop workbenches for auditing research and writing papers. The desktop app is partway through a move to a new component architecture; see [Known limits in this beta](#known-limits-in-this-beta). The full list is in [CHANGELOG.md](../../CHANGELOG.md).

## Highlights

- **Unit cycle in the engine.** `codex_run` with `cycle: true` runs Codex, VERIFY, ACCEPT and the review pack in one call, and a hook records the reviewer's verdict. Each dispatcher starts from a bounded module context (`orch module-context`, 16,384 bytes) and is bound to its own module; long tool output goes to files. `orch map --repo` lints the module map before dispatch. Each wish has its own store, workers and VERIFY commands get private scratch space, a running or verified unit is never dispatched twice, and a turn-limit stop exits with code 3 and continues with `--resume`.

- **Scheduling and routing.** A module starts as soon as its dependencies are verified, while other modules are still running, unless it conflicts with a running module in the code graph. Setup steps from `.axiom/setup.json` run during planning, and `orch report` writes receipts with wall time per verified unit and mean concurrency. Astra assigns each unit a tier (`terra`, `sol` or `astra`) and an effort, the architect writes them into the map, and the engine records each assignment. `terra` is the floor, luna is refused, and nothing else pins a worker model; a fix unit climbs one step. Core stages default to Opus for planning, escalation and close and Sonnet for build, configurable in `<home>/settings/models.json`.

- **Test-first units and review.** Briefs carry a CONTRACT and a TEST_MATRIX. The worker writes failing tests first, the engine records that RED evidence before implementation, and after VERIFY a self-check compares contract, tests and diff. In routed wishes (every map the architect writes is routed), unit reviews default to the Astra reviewer on Codex; policy `reviewer` can select `claude`, `astra-max` or `both`. Blocker and major findings get one quick Claude check, and a fix unit is refused when that check rejects its findings. `axiom stats` reports review counts and finding, rejection and escape rates. Approvals are recorded as exactly-once events, and only a person approves or denies them (`axiom approval`).

- **Background service and storage.** Closing the desktop window detaches: wishes keep running in `axiom serve`, and the app reattaches with live state. On Windows the tray offers **Open**, **Pause all** and **Quit**; **Start at login** is off by default and resumes interrupted wishes, except ones you stopped. A ledger records each directory Chronos creates by class and owner. `axiom storage` lists usage, `axiom storage clean` plans first and acts only with `--yes`, and worktrees are never removed automatically. Routine cleanup removes stale scratch, unused build caches and old engine copies; logs and evidence are compressed, not deleted. Wishes, setup steps and managed batches check free space first. When space runs low during a wish, Chronos frees safe classes, then pauses the wish with a distinct `disk_space` reason; free space and resume. See [storage](../storage.md).

- **Native graph.** A code and memory graph built in Rust (syn for Rust, hand-written lexers for Python, TypeScript and JavaScript, no external service) serves the `graph_explore` bridge tool, `axiom graph refresh|explore` and `axiom dream`. `CONSTRAINTS.md` at the project root is prepended to unit briefs, and a wish's first prompt gets a bounded launch context.

- **Modes beyond the wish.** `axiom do --scope PATH --verify CMD "<task>"` runs one scoped quick task; review is opt-in. Chat, a read-only plaza that routes each question to at most three members, and routines are new. Routines use cron or event triggers, stay off unless enabled in `<home>/modes/routines.json`, and run in the background service. Chat and plaza can promote a conversation to a quick task or a wish. Receipts record elapsed time and cost, or say `cost unknown`. See [modes](../modes.md).

- **Research and paper workbenches.** The desktop Research page audits a project described by `research-manifest.json` and reads it only: a PRISMA source funnel with sampling and spot-checks, evidence with page jumps and contradictions, a schema-aware dataset table, and CSV, evidence-bundle and snapshot exports that hand off to Write paper. Write paper drafts a manuscript in four passes (Astra draft, Fable revision, Gemini Hydrogen revision, Fable style), each model configurable. It shortlists journals from OpenAlex, SJR and DOAJ plus an optional local JCR CSV or XLSX, verifies citations with Crossref, compiles elsarticle and IEEEtran templates with Tectonic, draws vector figures, and blocks readiness on fake citations or unsourced numbers. The style pass may change wording only, never claims, quantities or citations, and a disclosure statement lists the AI use. See [research-manifest](../research-manifest.md) and [paper-3.0](../paper-3.0.md).

- **Council, quotas and platform.** Argon now speaks in every council round by default; `AXIOM_COUNCIL_ARGON_EVERY_ROUND=0` restores the single review. Hydrogen/Flash and Argon have separate quota pools in budgets and the quota strip. With advanced research, the council can run a research program before planning; `axiom research-budget estimate` gives a spend estimate from earlier runs, and `raise` asks a person before raising a program's cap. Workshop modules (`axiom workshop`) talk to the host over a versioned JSON-lines API with declared permissions; high-risk permissions need a person's confirmation. Laya, an optional local decision model, runs in shadow mode only and changes no decision. `axiom evolve` sorts problems into failure classes, and `axiom extreme on` requests Codex's fast service tier and records whether the account accepted it.

- **Desktop.** New pages: Storage, Research, Write paper, Chat, Quick task, Plaza, Routine and live pages for sessions hosted by the background service. The Run view shows live stages, heartbeats, plain-language events and notices for turn-limit stops and degraded council members, with a redrawn council and dual-core view. Wishes can be marked read or archived, Usage can scope to one wish and compare two, and the New wish dialog adds templates, a wish optimizer and GitHub issue import through `gh`.

- **Engine fixes.** Store-lock waits inside one process now have a deadline, so a stuck call fails with an error instead of hanging the bridge. A module whose ACCEPT passes after its units' reviews now counts as verified. Released modules are claimed again automatically once they are ready. The hook rejects `run_in_background` passed as a string such as `"true"` and asks for the JSON boolean. `orch module-context` returns faster.

## Optional and paid

Off unless you turn them on: the advanced research council, the Astra adjudicator (default caps of 5 rulings and $5), the PM/QA reviewer, dual-core mode, routines, extreme mode, Laya, workshop modules and Start at login. The council now includes Argon in every round by default, and Argon's token cap applies across its calls; the default caps stay Fable $5, Astra 200k tokens, Argon 400k tokens and 3 rounds per phase. Write paper calls Astra, Fable and Gemini Hydrogen, with Fable capped per paper run (default $5). The wish optimizer calls Claude. Tectonic (paper templates and figures), `gh` (issue import) and ONNX Runtime (Laya) are used only when present. Model services use their own quotas. Usage dollars remain API-price equivalents, not subscription charges.

## Install

Download and extract `axiom-chronos-3.0.0-beta.1-windows-x64.zip`, then run:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
```

On Linux, extract `axiom-chronos-3.0.0-beta.1-linux-x64.tar.gz` and run `sh ./install.sh`.

Close running Chronos programs before upgrading. From this release on, closing the desktop window leaves the background service running, so choose **Quit** from the tray first. The installers also update the Claude plugin; the plugin and `axiom` must come from the same release, and a mismatch stops a wish with instructions. Data in `~/.axiom` from 2.0.x stays readable, and a wish stopped under 2.0.1 resumes without running or charging its verified units again. Usage and evolve also read archived (`.gz`) transcripts. Installers, options and prerequisites are unchanged from [2.0.0](2.0.0.md).

Build from Rust:

```sh
cargo install --git https://github.com/xinhi6716/axiom-chronos --tag v3.0.0-beta.1 --locked --bin axiom
cargo install --git https://github.com/xinhi6716/axiom-chronos --tag v3.0.0-beta.1 --locked --features app --bin chronos
```

The desktop build is for Windows.

## Known limits in this beta

- **Desktop migration.** The move to the shared component, data and facade layers is partial. Migrated and verified: the app root, layout, components, motion, charts, data, the facades, sessions and settings, Research, Write paper and the council view. Still being moved for 3.0.0: Wishes, the side panels, Run, the modes pages, the window shell, Mini and the overlays. The final screenshot and performance gates have not run.
- **Graph briefs.** In the live A/B, graph-built briefs used a median 24.08% more Claude input than today's briefs and missed each scenario's main source file, so unit briefs are not built from the graph. Word-level seeding has since improved the offline results; it has not been re-measured live. Short CJK queries find no seeds. See [graph-ab](../graph-ab.md).
- **Not in this version.** The vault and memory upgrade is not included; the Research page says so where it would appear.
- **Background service.** The tray and Start at login are tested through recording adapters; the real tray icon and login registration have not been checked by hand. Taking over a hosted session, typing into it or handing it back from the desktop is refused, because the service protocol has no such operations.
- **Safety and accounting.** Astra's read-only tools are enforced by its prompt, not by a sandbox. Workshop permissions are checked at the API boundary and at spawn; they are not OS isolation. Claude replies that cannot be parsed are not charged in Usage. Self-check findings are saved in `reports/<unit>.selfcheck.json` but are not passed to the reviewer automatically.
- **Paper.** Figures cover line, scatter, error-bar and bar plots. The figure and PDF checks are mechanical and do not judge publication quality. elsarticle and IEEEtran are verified; sn-jnl and achemso are unconfirmed.
- **Laya.** Laya needs ONNX Runtime, which the release does not include. The runtime and model hashes in `tools/laya/pins.json` are not recorded yet, so the first fetch is trusted on first use.
- **Plugin channel.** The plugin installed from the repository's default branch is now 3.0.0-beta.1, so a 2.0.1 install that updates its plugin must also install the 3.0.0-beta.1 programs; the wish stops on a version mismatch.
- Protocol tests use scripted stand-ins for Claude and Codex; live-model results vary by project. The desktop app is Windows only. Existing 2.0.x limits still apply.

## 繁體中文

Axiom Chronos 3.0.0-beta.1 是 3.0 的 GitHub 預先發行版。引擎在單一呼叫內完成單元的施工、驗證、驗收與審查包；模組所依賴的模組驗證完成後就立即開工；每個單元都經路由指定 Codex 等級。關閉視窗後，願望繼續在背景服務執行。新增原生程式碼與記憶圖、含磁碟防護的儲存空間帳本、願望以外的模式，以及研究稽核與論文撰寫的桌面工作台。桌面應用程式正改用新的元件架構，尚未完成；見[本版已知限制](#本版已知限制)。完整清單見 [CHANGELOG.md](../../CHANGELOG.md)。

### 重點

- **引擎內的單元循環。** `codex_run` 加上 `cycle: true` 在一次呼叫內完成 Codex、VERIFY、ACCEPT 與審查包，hook 記錄審查員裁決。調度員從有上限的模組上下文開始（`orch module-context`，16,384 bytes），只能處理自己的模組。`orch map --repo` 在派工前檢查模組圖。每個願望有獨立 store，工作者使用私有暫存空間，進行中或已驗證的單元不會重複派工；達回合上限時以代碼 3 結束，可用 `--resume` 接續。
- **排程與路由。** 依賴驗證完成的模組立即開工，其他模組仍在執行也一樣，除非與執行中模組在程式碼圖上衝突。`.axiom/setup.json` 的準備步驟與規劃同時進行，`orch report` 寫出每個驗證單元的時間與平均並行度。Astra 為每個單元指定等級（`terra`、`sol`、`astra`）與推理強度；`terra` 是下限，luna 會被拒絕，修補單元往上升一級。核心各階段預設 Opus（規劃、升級、收尾）與 Sonnet（施工），可在 `<home>/settings/models.json` 調整。
- **測試先行與審查。** brief 附 CONTRACT 與 TEST_MATRIX；工作者先寫會失敗的測試，引擎記錄 RED 證據，VERIFY 後再由自我檢查比對。有路由的願望（architect 寫的模組圖都有路由）預設由 Codex 上的 Astra 審查員審單元；blocker 與 major 發現先經 Claude 快速核對，核對駁回時不建立修補單元。`axiom stats` 顯示審查數量與各項比率；核准只由人透過 `axiom approval` 決定。
- **背景服務與儲存空間。** 關閉視窗只中斷連線，願望在 `axiom serve` 繼續執行。Windows 系統匣提供 Open、Pause all、Quit；Start at login 預設關閉。`axiom storage` 列出用量，`axiom storage clean` 先列計畫，加 `--yes` 才執行；worktree 不會自動刪除，日誌與證據只壓縮不刪除。空間不足時先釋放安全類別，仍不足就以 `disk_space` 原因暫停願望，騰出空間後接續即可。
- **原生圖。** Rust 實作的程式碼與記憶圖（Rust 用 syn，Python、TypeScript、JavaScript 用手寫詞法分析器，不需外部服務）提供 `graph_explore`、`axiom graph refresh|explore` 與 `axiom dream`。專案根目錄的 `CONSTRAINTS.md` 會加在單元 brief 前面。
- **願望以外的模式。** `axiom do --scope PATH --verify CMD "<任務>"` 執行一個限定範圍的快速任務。新增聊天、最多選三位成員的唯讀廣場，以及在 `<home>/modes/routines.json` 啟用後才執行的例行工作。聊天與廣場可升級為快速任務或願望。
- **研究與論文工作台。** Research 頁唯讀稽核以 `research-manifest.json` 描述的專案：PRISMA 來源漏斗、證據與頁面跳轉、資料表，以及可交給 Write paper 的匯出。Write paper 以四輪（Astra 初稿、Fable 修訂、Gemini Hydrogen 修訂、Fable 文風）撰寫，篩選期刊、以 Crossref 核對引用、用 Tectonic 編譯 elsarticle 與 IEEEtran；假引用或無來源數字會阻擋就緒。文風輪只改措辭，不改主張、數量或引用。
- **議會、額度與平台。** Argon 預設參與每一輪議會（`AXIOM_COUNCIL_ARGON_EVERY_ROUND=0` 可改回單次審查）；Hydrogen/Flash 與 Argon 額度池分開計算。`axiom research-budget estimate` 依過往紀錄估算花費，`raise` 須由人確認。Workshop 模組透過有版本的 JSON-lines API 與宣告的權限運作。Laya 只在影子模式記錄預測，不改變任何決定。`axiom extreme on` 請求 Codex 快速服務等級並記錄是否被接受。
- **桌面。** 新增 Storage、Research、Write paper、Chat、Quick task、Plaza、Routine 與背景 session 頁面。Run 顯示即時階段、心跳、白話事件，以及回合上限與議會成員降級提示。願望可標為已讀或封存，Usage 可看單一願望並比較兩個願望；許願視窗新增範本、願望優化與 GitHub 議題匯入。
- **引擎修正。** 同一程序內等待 store 鎖設有期限，卡住的呼叫會回報錯誤，不再讓 bridge 停擺。單元審查之後才通過的模組 ACCEPT 也算模組驗證。已釋放的模組就緒後會自動重新認領。hook 拒絕以字串（如 `"true"`）傳入的 `run_in_background`，要求 JSON 布林值。`orch module-context` 回應更快。

### 選用與費用

議會、Astra 裁決者（預設上限 5 次裁決、$5）、PM/QA 審查員、雙核心模式、例行工作、極速模式、Laya、Workshop 模組與 Start at login 都預設關閉。議會現在預設每輪都有 Argon，其 token 上限跨各次呼叫合計；預設上限維持 Fable $5、Astra 200k、Argon 400k tokens、每階段 3 輪。Write paper 會呼叫 Astra、Fable 與 Gemini Hydrogen，每次論文的 Fable 花費有上限（預設 $5）。願望優化會呼叫 Claude。Tectonic、`gh` 與 ONNX Runtime 有安裝才會使用。Usage 金額是 API 定價等值金額，並非訂閱帳單。

### 安裝

Windows 解壓 `axiom-chronos-3.0.0-beta.1-windows-x64.zip` 後執行上方 PowerShell 安裝指令。Linux 解壓 `axiom-chronos-3.0.0-beta.1-linux-x64.tar.gz` 後執行 `sh ./install.sh`。升級前先關閉 Chronos；從本版起，關閉視窗後背景服務仍在執行，請先在系統匣選擇 Quit。安裝程式會一併更新 Claude 插件；插件與 `axiom` 必須同一版本，不一致時願望會停止並說明處理方式。`~/.axiom` 中 2.0.x 的資料仍可讀取，2.0.1 停下的願望接續時不會重跑或重複計費已驗證的單元。安裝選項與必要工具同 [2.0.0](2.0.0.md)，也可用上方 Rust 指令建置；桌面僅支援 Windows。

### 本版已知限制

- **桌面移轉。** 已移轉並驗證：應用程式根、版面、元件、動態、圖表、資料、facade、sessions 與 settings、Research、Write paper 與議會視圖。3.0.0 前仍在移轉：Wishes、側邊面板、Run、各模式頁面、視窗外殼、迷你視窗與覆蓋層；最終截圖與效能關卡尚未執行。
- **圖譜 brief。** 實測 A/B 中，以圖建立的 brief 使 Claude 輸入中位數多出 24.08%，且每個情境都缺少主要原始檔，因此單元 brief 不由圖建立。逐詞種子改善了離線結果，尚未重新實測。簡短 CJK 查詢找不到種子。
- **未納入本版。** 保管庫與記憶升級不在本版，Research 頁會在相應位置註明。
- **背景服務。** 系統匣與 Start at login 以記錄用替身測試，真實圖示與登入註冊尚未人工確認。桌面無法接管、輸入或交還背景 session，因為服務協定沒有這些操作。
- **安全與計費。** Astra 的唯讀工具只由提示約束，並非沙箱。Workshop 權限在 API 邊界與啟動時檢查，不是作業系統隔離。無法解析的 Claude 回覆不計入 Usage。自我檢查發現存在 `reports/<unit>.selfcheck.json`，不會自動交給審查員。
- **論文。** 圖表支援折線、散佈、誤差線與長條圖；圖表與 PDF 檢查是機械檢查，不評斷出版品質。elsarticle 與 IEEEtran 已驗證，sn-jnl 與 achemso 未確認。
- **Laya。** 需要 ONNX Runtime，發行包不含。`tools/laya/pins.json` 尚未記錄 runtime 與模型雜湊，首次下載採首次信任。
- **插件來源。** 從儲存庫預設分支安裝的插件現在是 3.0.0-beta.1，因此更新插件的 2.0.1 安裝也必須一併安裝 3.0.0-beta.1 的程式；版本不一致時願望會停止。
- 協定測試使用腳本替身，真實模型的表現依專案而異。桌面應用程式僅支援 Windows。2.0.x 的既有限制仍適用。
