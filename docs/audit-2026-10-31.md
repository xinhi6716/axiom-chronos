# Codex 專用版：三輪修正與量測

基線：`f3a846a70e1903fb39722692a80412cdecf37887`。工作分支：`codex-audit-three-rounds`。原有未提交圖標修改保留，與工程驗收分開。

## 驗收與資料使用

- 固定目標：目前 Codex 對話為核心；bridge 僅調度子代理，不另啟核心。Astra MAX 做獨立研究；Terra high 調度／元件；Sol high 裝配；記憶核心 Terra medium；Luna 處理文件、圖片及大量非工程工作。
- 保留 wish/research 入口、原 bridge 工具名稱與必要的隔離／證據／重用機制。Rust 為執行期；既有 Python fake 及量測腳本只用於測試。
- 每輪記錄更改、驗證、性能、效率、token、任務結果、調度、恢復、維護成本。不因結果不佳修改驗收門檻。
- 已用於診斷、修正或策略選擇的案例均屬已曝光開發集。前後同題比較可量測成本，不能宣稱獨立泛化驗收；最後另留未用於調整的案例。
- 模型消耗使用回傳的 input/cached/output/total tokens；total 是累積上下文計數，不能當成未快取的計費數量。時間包括 API／排隊波動，極小樣本不建立穩定加速結論。
- fake 結果只證明協定／狀態機，不代表真實模型工程成功率。所有未實測的收益均為假設。

## 研究來源與適配

[Stop That Shit](https://github.com/lennney/stop-that-shit/tree/17ffc9f5108381916f4f9b019d61b759626c4a71) 的 scope、無用防禦、意圖、重複作業四類準則用於稽核；不安裝另一套流程插件。Rust 不會自動修正政策、狀態或證據身份錯誤。既有 snapshot 用於拒絕過期重用，因此不是應刪除的裝飾 hash。

[RSI-Anything](https://arxiv.org/html/2610.13912v1) 區分預測與實際觀察，要求固定評估條件、分開更新資料與驗收資料，以及組合相容性驗收。此處優先採其有界策略更新與保留／回退原則；未具備資料和校準證據前，不引入可訓練 world model，也不宣稱重現其實驗收益。

[Codex 官方 app-server](https://learn.chatgpt.com/docs/app-server) 與 [設定參考](https://learn.chatgpt.com/docs/config-file/config-reference) 用於核對執行緒設定；設定存在不等於隔離有效，另以本機回報與測試確認。不修改使用者全域官方插件／服務設定。

## 優化候選與適用條件

| 方向 | 適用條件／預期收益 | 代價／風險 | 驗證方式 |
|---|---|---|---|
| 移除第二核心 | 桌面主對話已具核心；減少模型輪次與重複上下文 | 外部 session 綁定、取消與恢復須完整 | fake assert 零 core thread；真實子代理冒煙 |
| 角色政策單一來源 | 模型／effort／工具／技能共同維護 | 不建泛用政策框架 | 角色矩陣測試、重複定義數、變更檔案數 |
| thread-local plugins/skills 最小化 | 子代理無需官方整合時 | 明確需要的能力必須可選回；不動全域 | started MCP、有效配置、相同任務 token |
| 只回傳摘要與必要證據 | brief/報告／記憶內容過長 | 過度裁切可能漏資訊 | 任務正確率、載入 bytes、輸入 token、二次讀取數 |
| 內容身份驅動重用 | 內容、契約、依賴沒有相關變化 | 身份計算成本；不要每檔開多個 Git 程序 | unchanged reuse 零模型 turn；dirty N 檔短測 |
| 有界並行與事件通知 | 獨立 unit；帳號能承受並行 | 錯誤鎖設計可能阻塞 nested callback | 兩個慢 fake 重疊、上限、取消延遲 |
| 明確停止／不確定狀態 | timeout、斷線、拒絕中斷 | 不確定時可能犧牲可用性，避免重複副作用 | 故障注入、停止後零新工具、受控回收 |
| 選擇性驗證 | 已約定只需 focused check；無新證據 | 依賴範圍判錯會漏測 | 固定驗收，檢查不相關 review 不使 fulltest 過期 |
| 本地記憶檢索 | 重複任務、穩定接口知識 | 過期記憶／誤命中 | hit@k、stale 拒用、摘要/正文 bytes、模型 token |

不採用沒有當前需求的分散式排程平台、向量服務、多 provider 抽象層、無上限遞迴研究或自我調高驗收分數。檔案系統技能隔離與原生模型的完整權限隔離不同，不能以提示詞冒充 sandbox。

### 第二輪：未完成裝配的整合驗收

前次 Sol 裝配於 902 秒逾時並確認終端中斷；保留其全部未提交修改，不採信先前遭 in-repo Cargo target 越界污染的元件自報。本次先以既存外部 target 實跑完整套件，現況為 227 個頂層測試通過、2 個性能 probe ignored；這不代表新增的第二輪要求均已覆蓋。CLI／engine 已改成外部對話為核心及 Terra medium 記憶角色的期望，保留該行為，不恢復額外核心或 Luna 記憶。

整合保留 dispatcher 的 root goal／change 授權繼承、首次派工前初始化 store、跨 RPC callback 的取消域、scope／證據檢查與 quarantine；另補齊：

- **跨程序排他 claim**：以 `create_new` 原子取得 store 的 `.worker.claim`，涵蓋模型與 VERIFY 全生命週期。同程序不重疊 scopes 可共用 lease，最後一個 claim 釋放才刪除；正常失敗／abort 亦釋放。程序崩潰不自動偷鎖，避免遠端 writer 尚在運作便重試；明確 recovery 拒絕仍存活的外部 owner 或本地非隔離 worker。
- **實際模型身份**：worker 缺少實際 model 時不啟動 turn、不給要求模型的證據。review／rewrite 檢查實際角色；報告、獨立審查與 stage 記錄使用實際回傳版本，而非要求版本。錯誤角色不取得成功證據。
- **取消與遲到完成**：Host 與直接 worker 都保留 `terminal_status`，但已取消／逾時的請求不能因遲到 `completed` 被算成功。未確認終止仍進 quarantine，不能由一般 abort 解除。

| 驗收風險 | 實際測試與負向控制 |
|---|---|
| Host → Agent／nested Agent／callback VERIFY／Bash 取消 | `tests/bridge/dispatcher_cases.rs`：notification 與 EOF 均覆蓋；以可觀察開始訊號而非盲等觸發取消，Bash 父子 PID 均須停止，取消回應不得 completed；保留其他請求的取消域。直接 worker 另測遲到完成的 timeout／cancel，及未確認 start／interrupt |

#### 命令與結果

以下 Cargo 命令均先設定同一個既存外部 target；本次環境原值指向 repo 內 `target`，不沿用該值，也沒有刪除 repo 內既有產物。

```powershell
$env:CARGO_TARGET_DIR = Join-Path $env:TEMP 'chronos-assembler-target'
```
